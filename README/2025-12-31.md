
B. 用你自己的 demo 项目，通过 yarn link 把 React 源码包链接过去（最适合长期学习）

1）先在 React 仓库里构建出可被 link 的产物
还是在 React 仓库根目录：
yarn build

构建成功后，一般会在类似路径生成产物（不同版本路径不同）：
build/nodemodules/react
build/nodemodules/react-dom

你可以用下面命令确认有没有 build 出来：
ls build/nodemodules | head

2）在 React 仓库里把包 link 出去
在 React 仓库根目录执行（如果不行就按下面“进入具体包目录”的方式）：
cd build/nodemodules/react
yarn link

cd ../react-dom
yarn link

如果你没有 build/nodemodules/... 这种结构，那就用 find 找一下 react/package.json 在哪里，例如：  
find . -path "*react/package.json" | head

3）在你的 demo 项目里接入 link
进入你的 demo 项目：
yarn link react
yarn link react-dom

然后启动你的 demo：
yarn dev
或
yarn start

4）避免 “Invalid hook call / 两份 React” 问题（非常常见）
如果你遇到 Invalid hook call，99% 是因为项目里同时存在两份 React（一个来自 link，一个来自依赖树）。

处理思路（给你最常用的两种）：

方式 1：锁定只用 link 的那份
确认 yarn why react 看看是不是还有别的 react 来源
确保你的 demo 项目的 nodemodules 里没有另外装一份不同路径的 react（必要时删 nodemodules 重装）

方式 2：用 resolutions 强制依赖收敛（yarn classic 常用）
在 demo 的 package.json 加：
{
  "resolutions": {
    "react": "link:react",
    "react-dom": "link:react-dom"
  }
}
然后：
rm -rf nodemodules
yarn

C. 确保能断点：sourcemap + 调试方式（Chrome / VSCode）

1）确认构建产物带 sourcemap
在你 demo 跑起来后，打开浏览器 devtools：
Sources 面板里看能否找到 packages/react-dom/... 或类似“源码路径映射”
Network 里看 .map 文件是否请求成功（比如 react-dom.development.js.map）

如果你在 Network 里看不到 .map，说明构建可能是 production 或关闭了 sourcemap。
你需要：
用 dev 构建（development build）
或开启 sourcemap 的构建脚本（不同仓库脚本名字不同）

2）Chrome DevTools 断点方式（最简单）
浏览器打开你的 demo 页面
DevTools → Sources
Ctrl/Cmd + P 搜索关键词，比如：
   - beginWork
   - commitRoot
   - performUnitOfWork
   - dispatchSetState / dispatchActionState（具体函数名随版本）
在函数入口打断点
页面里触发一次更新（点击按钮 setState），观察调用栈

3）VSCode 断点方式（更顺手）
如果你用 Vite/webpack dev server 跑 demo，推荐用 JavaScript Debug Terminal：
VSCode → Terminal → JavaScript Debug Terminal
在这个终端里启动你的 demo：yarn dev
VSCode 里直接打开映射出来的源码文件打断点
触发更新即可停住
