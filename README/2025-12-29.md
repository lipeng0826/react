下面给你一条“可执行”的 React 源码学习路径，默认你已经是深度使用者、看过源码课，但现在需要把“看懂”变成“能定位/能改/能验证”。

1）先把仓库跑起来：建立“可调试”的学习环境（1 天内）
目标：能断点进 React 源码、能改一行看到效果、能跑测试。

切换到18.3.1版本

要切到 React 的 v18.3.1，通常是切到对应的 tag。按下面步骤来：

1）先更新本地仓库的 tag
在你 fork 的本地仓库目录里执行：
git fetch --all --tags

2）切到 v18.3.1 tag
git checkout v18.3.1

必做清单
安装依赖 & 构建

- yarn（React 仓库通常用 yarn classic）
- yarn build 或 yarn build react/index,react-dom/index（看项目脚本）

用本地构建包跑一个 demo

- 推荐用仓库自带的 fixtures 或 examples
- 或者用 yarn link / pnpm link 把 react、react-dom 链接到你自己的小项目里（避免 monorepo 里绕来绕去）

能断点

- 确认构建产物带 sourcemap
- 用 Chrome DevTools / VSCode JS Debugger 断到 packages/react-dom/... 或 packages/react-reconciler/...

这一阶段不要急着看全局架构，先把“我能进源码”这件事做实，否则后面全是纸上谈兵。

2）用“任务驱动”方式切源码：一次只追一条主线（2~7 天游泳）
不要从头读文件夹。你已经看过视频了，最有效的是：拿一个具体行为 → 找入口 → 追调用链 → 写笔记 → 做验证实验。

推荐 4 条主线（按收益排序）
更新链路：setState/useState 到 DOM 变更

- 你要回答的问题：一次更新经历了哪些阶段？哪里决定优先级？哪里可中断/可恢复？
- 建议实验：在关键函数打日志，观察一次点击触发的调用顺序（比如 render/commit 前后）

Fiber 与 Reconciler：beginWork/completeWork 做了啥

- 你要回答的问题：为什么需要 Fiber？diff 发生在哪里？effect 列表怎么生成？
- 建议实验：改动某个分支判断，让某类节点强制走不同路径，看页面变化 & 测试变化

Commit 阶段：DOM 创建、属性更新、ref、layout effect

- 你要回答的问题：为什么有 layout/passive effects？执行顺序如何保证？
- 建议实验：写一个包含 useLayoutEffect/useEffect/ref 的 demo，验证执行时序

调度与优先级（Scheduler/Lanes）

- 你要回答的问题：不同事件优先级怎么映射到 lanes？并发模式下如何让出主线程？
- 建议实验：大列表渲染 + 输入框，观察输入是否被卡住；再定位是谁在让出/恢复

3）读源码的“最小地图”：你需要先认这些目录（避免迷路）
不同版本目录可能略有差异，但大体是：

packages/react：API 表层（createElement、hooks 入口等）
packages/react-dom：DOM 渲染入口、事件系统、commit 到 DOM
packages/react-reconciler：核心 reconciler（Fiber、begin/complete、commit 组织）
packages/scheduler：调度（如果版本拆分如此）
packages/shared：共享工具、flags、常量

你学习时每次只问：当前问题属于“API 表层 / Reconciler / DOM commit / 调度”哪一层？  
先分层再追代码，会快很多。

4）强烈建议：用“可复现”的输出写笔记，而不是写概念
你已经懂大概原理了，接下来要让自己能“定位问题”。推荐笔记格式：

现象：点击按钮触发更新，为什么 effect 延后？
入口：从哪里进（文件/函数）
关键数据结构：Fiber 上哪些字段在变（lanes、flags、memoizedState…）
关键阶段：render / commit（再细分）
我做的实验：改了什么/加了什么日志/现象是什么
结论：一句话 + 关键调用链

5）每周一个“源码改动小项目”：把学习闭环
下面这些都很适合练手（不会太大，又能触到核心）：

加一个调试开关：在开发环境输出某类 Fiber 的 flags/lanes
改一个 hooks 的警告信息：串起 hooks 解析链路
给事件系统加日志：理解事件优先级如何影响更新
写一个针对某 bug 的最小测试：学会跑测试、定位回归

目标不是贡献 PR，而是让你形成“改→跑→验证→回滚/提交”的肌肉记忆。

6）给你一个 14 天游泳计划（你可以直接照着执行）
Day 1：跑起来 + 断点进入源码 + 能本地替换到 demo
Day 2-3：setState/useState 更新链路（render→commit）
Day 4-5：beginWork/completeWork + diff（对比 key/无 key）
Day 6：commit 阶段（ref/layout effect/passive effect 顺序）
Day 7：写一篇“从点击到 DOM 变化”的调用链笔记
Day 8-10：Scheduler/Lanes（配合大列表 demo）
Day 11：事件系统 → 优先级映射
Day 12：写一个小改动 + 测试
Day 13：复盘：把各阶段关键函数整理成一张“导航图”
Day 14：挑一个真实业务问题，用源码定位一次原因（哪怕只是解释清楚）
